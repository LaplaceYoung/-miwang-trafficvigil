# 设计思路

## 一、总体设计目标

密网巡哨 TrafficVigil 的设计目标是把复杂的加密流量分析任务组织成评审容易理解、用户容易操作、工程结构清晰的系统闭环。平台围绕“输入是什么、系统怎么分析、结果如何呈现、结论怎样支撑安全研判”四个问题展开。

## 二、产品设计思路

### 1. 以任务流组织界面

系统界面按照真实工作流组织：

1. 导入 PCAP 或启动实时抓包。
2. 查看 VPN、非 VPN、加密 IM 的分层分类结果。
3. 进入行为嗅探页面查看 chat、photo、file、video 等概率。
4. 进入群组关联页面查看用户、设备和公共群组关系。
5. 生成结构化分析报告。

这种组织方式形成清晰的任务推进顺序，并保持平台化操作体验。

### 2. 以核心指标建立第一印象

首页优先展示 98.7%、90.2%、89.4%、6.32Gbps、0.38ms 等关键指标。评审进入页面后可以快速理解作品价值：准确率高、链路完整、实时能力强。

### 3. 以可视化降低技术理解门槛

加密流量识别涉及预训练、图神经网络、多模态图谱等复杂概念。页面通过雷达动效、堆叠分类图、行为概率条形图和关系图谱把抽象模型结果转化为直观画面，使技术逻辑更容易被评审和使用者快速理解。

## 三、系统架构设计

系统采用四层工程结构：

1. 数据接入层：负责 PCAP 上传、实时抓包、会话切分和元数据抽取。
2. 多层分类层：负责 VPN/非 VPN、SIM/非 SIM 和应用类别识别。
3. 行为与图谱层：负责用户行为嗅探和公共群组关联。
4. 可视化与报告层：负责结果可视化、结构化报告和成果呈现页面。

## 四、算法设计思路

### 1. 预训练解决标注稀缺

加密流量标注成本高，人工标注存在质量波动。系统先用大规模通用网络流量进行预训练，学习通用协议交互和字节序列特征，再使用任务数据进行微调。该思路提升了模型在少量标注数据条件下的适应能力。

### 2. 数据增强提升鲁棒性

真实网络流量中包含重传、抖动、背景应用和协议封装噪声。系统引入 RIFA 数据增强与噪声注入训练，让模型关注稳定判别特征。该策略面向运营商级混合网络场景，提升模型抗干扰能力。

### 3. 双粒度图建模提升表达能力

字节级图刻画单个数据包内部结构，流量级拓扑图刻画包与包、会话与会话之间的上下文关系。两个粒度互补后，模型可以同时捕捉微观字节模式和宏观通信行为。

### 4. 多模态图谱支撑群组溯源

群组关联依赖多源线索。系统将用户、设备、群组抽象为节点，将流量交互、时间依赖和协议转换抽象为边，通过图谱推理输出成员关联概率，使溯源结果具备结构化解释。

## 五、前端设计思路

前端采用 GitHub Pages 静态部署方式，保证作品主页访问稳定、部署轻量、材料复用效率高。页面视觉采用安全运营控制台风格，减少装饰性元素，突出系统感、数据感和作品材料可读性。

页面结构包括：

- 首页总览
- 核心指标区
- 检测链路区
- 混合流量分类中心
- 行为嗅探中心
- 群组溯源图谱
- 技术架构说明

## 六、仓库设计思路

仓库采用“前端平台 + 文档材料 + 核心流程代码”的组织方式：

- `index.html` 支撑 GitHub Pages 展示。
- `assets/` 存放样式、交互脚本、展示数据和截图。
- `docs/` 存放计算机设计大赛材料。
- `src/trafficvigil/` 存放核心分析流程代码。
- `examples/` 存放示例任务。

这种结构便于评审快速浏览，也便于团队后续补充真实模型权重、接口服务和实验数据。

## 七、部署拓扑与数据流

系统部署采用“静态前端 + 本地分析流程 + 结构化结果文件”的组合形态。GitHub Pages 承载前端可视化平台，负责账号登录、任务浏览、过程编排、图表呈现和报告导出；本地 Python 分析流程负责读取授权 PCAP、抽取元数据、执行分类与图谱推理；结构化 JSON 报告作为分析层和前端展示层之间的数据交换格式。

数据流如下：

```text
PCAP / 实时抓包
  -> 会话切分与元数据抽取
  -> VPN / 非 VPN 分类
  -> SIM / 非 SIM 分类
  -> 应用识别与行为嗅探
  -> 用户-设备-群组三维关系图谱
  -> JSON / CSV / PDF / PNG 报告输出
  -> 前端页面与 PPT 素材复用
```

这种部署方式兼顾在线访问稳定性、本地推理复现能力和竞赛材料生成效率。

## 八、模块协同流程

前端页面与系统链路一一对应：流量捕获中心对应数据接入层，综合检测工作台对应任务编排层，VPN 与 SIM 分析页面对应多层分类层，行为嗅探页面对应图神经网络推理层，公共群组匹配页面对应多模态图谱层，分析报告中心对应结论汇总层。每个页面都围绕同一任务对象组织字段，包括任务编号、输入文件、捕获摘要、分类概率、行为分布、群组证据链和导出结果。

接口数据采用任务对象统一驱动，避免不同页面之间指标口径分散。任务对象中包含 `capture`、`vpnResult`、`simResult`、`behaviorResult` 和 `groupMatch` 五类核心字段，前端图表、表格、图谱和报告预览都从该对象读取信息，从而保证系统链路、页面叙事和文档材料保持一致。
